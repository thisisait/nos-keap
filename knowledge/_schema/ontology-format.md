# Ontology format spec (`knowledge/ontology/`)

The git SoT for the **R3 layer**: the controlled verb registry and the moderated
typed edges. `lint.mjs` enforces this contract; `roundtrip.mjs` proves byte
identity over the repo's files, and `ontology-sot.test.ts` proves it over the
shapes the repo does not currently contain.

This layer is the *assertions* row of the Track D anchoring model
(`docs/specs/ontology-anchoring.md`): skeleton = `canonical/`, evidence = cards,
**assertions = here**, rules = R4 (not built).

```
knowledge/ontology/
  relation-types.json          # the controlled vocabulary
  relations/<partition>.json   # typed edges, one file per L0 of the taxonomy endpoint
  manifest.json                # derived counts (regenerated by dump; not compared)
```

## `relation-types.json`

```jsonc
{
  "version": 1,
  "types": [
    { "type": "exemplifies",          // the verb id — what `relations.type` references
      "label": "exemplifies",         // rendered on the edge
      "color": "#fbbf24",             // edge hue (null allowed)
      "description": "The source is an instance or example of the target.",
      "status": "seed" }              // seed | proposed | confirmed
  ]
}
```

`status` is the moderation state of the *verb itself*: `seed` ships in the code
floor (`RELATION_TYPE_SEED`), `proposed` was grown by the classifier and awaits
an admin, `confirmed` was accepted into the live palette. **A verb grown and
confirmed live exists only here** — the code seed cannot carry it, which is why
a registry that lives only in code loses moderated growth on every rebuild.

## `relations/<partition>.json`

```jsonc
{
  "version": 1,
  "partition": "03-applied-sciences-technology",   // must equal the filename stem
  "relations": [
    { "from": "fs:nos-docs:7f746226f951fb1f",      // node id | knowledge_objects.id
      "fromKind": "object",                        // node | object
      "to": "03.01.02",
      "toKind": "node",
      "type": "exemplifies",                       // must exist in relation-types.json
      "source": "derived",                         // derived | manual — NEVER toe
      "status": "confirmed",                       // proposed | confirmed | rejected
      "confidence": 0.82,                          // optional, 0..1
      "justification": "the card body names it",   // optional
      "model": "claude-sonnet-5",                  // optional — what typed it
      "createdAt": 1784916266 }                    // provenance, preserved across rebuilds
  ]
}
```

Optional fields are **omitted, not null** — a hand-written file that leaves them
out must round-trip byte-identically rather than gaining `"model": null` noise.

## Rules (lint gates)

1. **Partition placement.** A row belongs in the file named for the **L0 of its
   taxonomy endpoint** (`from` wins when both endpoints are nodes; `_objects`
   when neither is). Numeric roots use the canonical folder slug
   (`03` → `03-applied-sciences-technology`), slug roots use themselves (`nos`).
   This is the load-bearing rule: dump groups by it and ingest keys its markers
   by it, so a row in the wrong file makes the two disagree about ownership.
2. **The verb must exist** in `relation-types.json`. Importing an edge on an
   unregistered verb would route straight around the vocabulary gate the live
   moderation layer enforces; ingest drops such rows and names them.
3. **No duplicates.** The store is `UNIQUE(from_ref, to_ref, type)` — two rows
   with the same triple are one row, and the file must not pretend otherwise.
4. **`source` is never `toe`.** ToE edges are versioned by `canonical/` and
   mirrored into the store at boot; carrying them here too would create two
   sources of truth for one edge.
5. **`confidence` within 0..1** when present; `status`/`kind` within their enums.

## Identity

A row's primary key is derived, not stored:
`id = "r-" + sha1("<from> <to> <type>")[:16]` — byte-identical to
`relationId()` in `server/db.ts`. Ingest reproduces it so the server's upserts
land on the same row instead of creating a duplicate the app reads as a second
edge.

## Why absence is not emptiness

`dump` writes `relation-types.json` and `manifest.json` **unconditionally**, even
when both sets are empty. An absent file cannot be told apart from "this was
never dumped" — and that ambiguity is exactly what let a total loss of the layer
read as normal for two days. An empty file says empty out loud.
